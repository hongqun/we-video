# 手绘讲解

[返回安装说明](SETUP.md)

第 4 步选择“手绘讲解”，打开“设计手绘讲解”，描述想画的内容。独立 Agent 读取已确认口播和真实字幕时间，通过百炼生成线稿、检查绘制预算、上色并进行视觉复核；随后编译部位绘制和手写文字。可继续对话修改，查看完整成图，再带声预览并采用。

“手绘插画”保留原来的线稿和彩图上传流程。“手绘讲解”首期只提供网页百炼制作入口。

## 安装与配置

从项目根目录执行：

```bash
npm ci --prefix packages/handdraw-agent
python3 -m venv .venv-handdraw
.venv-handdraw/bin/python -m pip install -r scripts/handdraw/requirements.txt
```

已有手绘 Python 环境可直接复用。在根 `.env` 设置 `HANDDRAW_PYTHON` 为该环境 Python 的绝对路径，留空使用 `python3`。文本模型和百炼凭据继续使用现有根配置，百炼 HTTP 地址的地域和业务空间需与密钥一致。

根 `pipeline.config.json` 增加：

```json
{
  "handdrawAgent": {
    "enabled": true,
    "imageModel": "qwen-image-2.0-pro",
    "visionModel": "qwen3-vl-plus"
  }
}
```

`imageModel` 需支持百炼同步文生图和参考图编辑；默认使用同一个模型生成线稿及上色。`visionModel` 需支持图片理解。模型可用性以所配置业务空间为准。可选执行限制为 `timeoutMs`（默认 900000）、`maxSteps`（默认 32，模型与工具共用）和 `maxArtworks`（默认每轮最多 4 次完整生图尝试）。不会自动回退到另一供应商。

内置 Skill 位于 `packages/handdraw-agent/skills/we-video-handdraw/`，随 Agent 纳入 Git 和部署，不需要额外安装 sweety Skill。部署需保留整个 Agent 包、项目现有 `scripts/handdraw/`、本地手写字体，以及包内的笔顺资料和许可文件。绘制模块的来源和固定版本记录在 `resources/drawing-modules.lock.json`。字体、笔顺资料和实际编译源码均参与缓存身份。

## 声画与运行数据

配音和字幕仍由现有流程制作。Agent 通过原文短语及出现次数绑定每个绘制动作，程序从现有字幕推算触发时刻；字幕区间内是字符时间估算，并非重新进行逐字音频对齐。重复词需绑定具体次数，支持跨字幕短语。

同一短语触发的动作串行落笔，窗口截至下一个触发点；绘制最多占窗口七成，至少保留一秒阅读。自然绘制超出预算时自动加速，单动作最高五倍，出墨和笔尖同步；超过上限才要求减少细节或标签。不改变配音语速、字幕与口播边界。例如 54 秒路径在 16.4 秒窗口内，按 30fps 取整后约以 4.71 倍速绘制 11.47 秒，余下约 4.93 秒供阅读。

编译产物是透明 PNG 图层、无损时间图及 JSON 轨迹，没有中间 MP4。Remotion 根据当前帧重建描线、填色、手写和笔尖，预览与最终导出使用同一个组件；品牌、字幕和陪伴人物沿用全片设置。文字统一使用本地手写体“站酷快乐体”的真实轮廓，汉字笔顺资料只辅助笔画排序；文字默认四倍快速书写，缩短抬笔停顿，插画独立安排速度。字体缺字或文字溢出会阻止编译。

制作记录、失败素材、候选及不可变产物保存在任务的 `handdraw-explainers/<sceneId>/`。上色失败后 Agent 可复用当前镜头已经审核通过的线稿，仅修改上色指令继续制作。候选经过素材哈希、配准、布局、预算和完成图视觉复核后才能采用；生成新候选不会覆盖已采用内容。口播、配音字节、字幕时间、镜头边界、主题或人物布局变化后必须重新制作或复核，采用及导出前会重新检查。取消、中断或过期请求不能提交新候选。

视觉模型审核完成图不等于实际播放或试听。首次正式使用仍需人工带声预览检查笔尖与画面形成过程。

## 按需检查

只有明确需要时，从项目根目录运行：

```bash
npm run test:handdraw-explainer
npm run test:handdraw-explainer:python
```

回归使用本地替身和临时目录，不调用百炼。实际模型效果、连续播放和成片一致性需另行授权使用代表镜头验证。

### 失败恢复

已生成彩图但视觉复核失败时，Agent 优先通过 `resume_artwork` 对原版本继续复核；没有彩图时继续上色，保留已审核线稿。恢复调用与新图预算分开，单轮最多恢复四次。明确的画面问题应修改方案，而不是反复复核。

视觉请求遇到连接、限流或暂时服务错误时最多重试两次；生图请求断线可能已计费，不自动重复提交。复核格式问题在素材目录的 `*-review-error.json` 保存错误类型、字段路径和对应的四个数值坐标，不保存供应商原始正文、密钥或签名地址。任务失败保留首个具体问题。

### 视觉定位与追踪

百炼视觉报告明确声明 `coordinateSystem: "xyxy-1000"`，`bbox` 使用 `[左上x, 左上y, 右下x, 右下y]`，范围 0–1000。程序严格检查顺序与边界后转换为内部归一化 `[左, 上, 宽, 高]`；不猜测坐标格式，也不裁剪无效区域。定位方式参考 [Qwen 官方 2D grounding 示例](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/2d_grounding.ipynb)。

格式失败时，只在同一组图片上追加具体字段反馈修正一次；仍失败就终止本轮。模型、排队工具和最终发布入口共用终止守卫，不能在恢复或生成预算耗尽后换工具继续生图。保留已有素材，后续新请求可继续处理。

LangSmith 根节点为 `handdraw-request`，携带 jobId、sceneId 和 requestId，业务失败会同步标记根节点失败。百炼分别显示 `bailian-line`、`bailian-color`、`bailian-vision-review` 模型节点及实际模型名，不上传图片二进制、凭据或签名地址。追踪继承根 `.env` 配置，退出前等待上传。
